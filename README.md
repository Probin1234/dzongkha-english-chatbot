# Druk Kha — Dzongkha English Chatbot

**Repository:** `Probin1234/dzongkha-english-chatbot`  
**Application:** Druk Kha  
**Type:** Streamlit web application · AI-assisted English-to-Bhutanese-Dzongkha conversational assistant

Druk Kha accepts questions written in English and aims to answer them in **Bhutanese Dzongkha**, accompanied by a **Roman-letter pronunciation** and the **English meaning**. It combines an English-language reasoning model served through Groq with the CST NLP English–Dzongkha translation service. It also provides user accounts, saved conversations, a phrasebook, and an administrator-led language-review workflow.

> **Important:** Dzongkha and Tibetan share a writing system. Detecting Tibetan-script characters does **not** establish which language a passage uses. The application's review rules flag certain expressions for human checking; they are not a validated language classifier. AI-generated translations and pronunciations can be inaccurate and should be reviewed by a proficient Dzongkha speaker.

## Features

- **English chat input:** Ask a question or request an explanation in English.
- **Immediate chat display:** Your message appears before the AI response is ready.
- **Loading indicator:** Animated “Druk Kha is thinking…” status while processing.
- **Three-part answer:** Dzongkha response, Roman-letter pronunciation (or an explicit unavailable message), and English meaning.
- **Conversation history:** SQLite-backed chats per account, with new-chat and delete-chat controls.
- **Phrasebook:** Save useful replies and view the included grammar/phrase examples.
- **Admin Desk:** View basic statistics, manage users, teach verified phrases, and inspect recent replies.
- **Human-in-the-loop review:** Flag selected expressions for manual review, approve corrected text and pronunciation, or dismiss a flag.
- **Resilience:** CST requests are split into shorter English segments, retried on failure, and can use a Groq-based fallback if CST fails.
- **Responsive dark interface:** Streamlit layout with custom styling and Dzongkha font support.

## How it works

```text
English user message
        |
        v
Check exact greetings / admin-taught phrases
        |
        v
Groq model: interpret the request and compose a clear English answer
        |
        v
Clean English text and split into shorter segments
        |
        v
CST NLP: translate English segments to Dzongkha
        |   (retry; use Groq backup if CST rejects a segment)
        v
Groq model: generate Roman-letter pronunciation
        |
        v
Display Dzongkha + pronunciation + English meaning
        |
        +--> Review selected expressions in the Admin Desk
        |        |
        |        +--> Admin approves corrected phrase for future exact matches
        v
Store conversation in SQLite
```

### Translation and pronunciation details

1. **Groq reasoning:** `backend/translator.py` calls the Groq Python SDK, defaulting to `openai/gpt-oss-20b`. The model answers the user's question in straightforward English rather than merely translating the input instruction.
2. **Input preparation:** Unusual punctuation is normalized and Tibetan-script characters are removed from the English text sent to CST. This reduces mixed-language input errors, but does not guarantee CST availability.
3. **CST translation:** The app uses `https://nlp.cst.edu.bt/nmt/` and its website API endpoint. **This endpoint is not guaranteed to be a stable public API.** It may change or become unavailable.
4. **Recovery:** Failed segments are retried, then passed to a Groq-based backup translation. **Fallback output is not verified Dzongkha.** The current response contract does not display a per-segment provenance badge.
5. **Pronunciation:** Groq attempts to convert Dzongkha-script text into Latin-letter pronunciation. Script validation prevents showing Dzongkha characters as the pronunciation. **This does not validate phonetic accuracy.**
6. **English meaning:** The English meaning is the original English answer generated by Groq, not a verified back-translation of the final Dzongkha.

## Installation — Windows (PowerShell)

**1. Clone the existing repository:**

```powershell
git clone https://github.com/Probin1234/dzongkha-english-chatbot.git
cd dzongkha-english-chatbot
```

**2. Create and activate a virtual environment:**

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

**3. Install dependencies:**

```powershell
python -m pip install -r requirements.txt
```

**4. Set your private configuration in the current PowerShell session:**

```powershell
$env:GROQ_API_KEY = "YOUR_GROQ_API_KEY"
$env:GROQ_MODEL = "openai/gpt-oss-20b"
$env:DRUK_ADMIN_EMAIL = "your-email@example.com"
$env:DRUK_ADMIN_PASSWORD = "YOUR_STRONG_ADMIN_PASSWORD"
```

The admin environment variables are used to seed the initial admin account **when creating a new database**. Existing local accounts are not reset automatically when these values change. Do not publish real keys or passwords in code, screenshots or Git commits.

**5. Start the app:**

```powershell
python -m streamlit run app.py
```

Open the local address shown by Streamlit (usually `http://localhost:8501`). The computer needs internet access for Groq and CST requests.

## How to use

1. Open the web application and sign in or create a user account.
2. Type a question in English, for example **“What is a book?”**
3. The user message appears immediately; a thinking indicator remains visible while the backend runs.
4. Read the Dzongkha answer, pronunciation and English meaning. If pronunciation generation fails, the UI shows an unavailable message.
5. Save a useful answer to your phrasebook. Open earlier chats from the sidebar.
6. If you have an administrator account, open **Admin Desk** to teach phrases and review flagged responses.

### Human review and phrase teaching

The review module contains a **small, rule-based list of expressions** that may warrant a language check. It does not detect every Tibetan-style expression and can produce false positives. The administrator can inspect the generated response, enter corrected Bhutanese Dzongkha and pronunciation, and approve or dismiss the flag. Approved entries are stored in the SQLite glossary and reused for exact English-input matches. This is **retrieval-based feedback**, not model retraining.

## Local datasets and attribution

The project includes `data/opus_dz_en.tsv`, local textbook-style phrases, and `data/opus_dz_en.SOURCE.txt`. Consult the included source notes and independently confirm the original corpus license and suitability before redistributing or expanding its use. A corpus entry is not automatically proof of natural conversational Bhutanese Dzongkha. The current translator primarily uses admin-taught examples for guidance; the local corpus should not be described as a trained model.

## Testing

Check syntax without making API calls:

```powershell
python -m compileall -q app.py backend
```

Test Groq connectivity (requires a valid key and internet):

```powershell
python test_groq.py
```

Run a small integration test (requires Groq and CST availability):

```powershell
python test_translator.py
```

Suggested manual tests: greeting, short definition, long explanation, follow-up question, poem, save-to-phrasebook, admin correction, and deliberate CST failure. Review both script correctness and spoken pronunciation with a proficient Dzongkha speaker.

## Known limitations

- CST is an external website service and can reject input or become unavailable.
- Backup Groq translation may produce inaccurate or Tibetan-influenced language.
- Romanized pronunciation is AI-generated and is **not** a verified phonetic transcription.
- The language review rules are a small heuristic list, **not** an automatic Tibetan-vs-Dzongkha classifier.
- SQLite storage and account management are intended for a local academic prototype; production deployment requires additional security, access-control and operational review.
- An internet connection and an accessible Groq model are required for newly generated answers.
- The supplied test scripts are manual integration checks, not a complete automated quality-assurance suite.

## Privacy and security

- Never commit `GROQ_API_KEY`, `.env`, `.streamlit/secrets.toml`, or a populated SQLite database.
- This repository package intentionally excludes local chat/account data and replaces hard-coded default account passwords with environment-configured initial credentials.
- Use a strong unique admin password. Protect user data and avoid sharing database backups publicly.
- Do not assume the prototype is ready for public production hosting without a security review.

## Academic purpose

This project demonstrates an AI-assisted conversational pipeline, translation-service integration, Streamlit user experience, local data storage, and human-in-the-loop correction. Its central goal is to support Bhutanese Dzongkha rather than treating all Tibetan-script text as interchangeable.
